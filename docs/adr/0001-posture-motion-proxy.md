# posture 特征用运动强度代理，而非方向姿态

**Status**: accepted（2026-09-05）

数据字典将 `posture` 定义为 accel 三分量方向判定的四态（0躺/1侧/2爬/3坐站），但该定义依赖固件方向辅助字段，而当前 MQTT 数据包只有 `imu_accel_mean`/`imu_gyro_mean` 标量，且 MVP 硬件无摄像头，婴儿真实姿态不可知。决定在 feature_spec 1.4.0 中用 motion_mean 阈值做运动代理姿态（still/low/high → 0/1/2），并修订数据字典注明此为实现代理而非口径变更。

## Considered Options

- **扩充数据包格式加方向字段**：依赖 ESP32-S3 硬件到位与固件排期，违背"AI 模型任务独立先行"的前提，且无法在无硬件时验证。
- **剔除 posture 砍为 14 维**：违反 15 维特征契约；姿态（哪怕粗糙代理）对醒/睡判断有真实信息量，主动砍特征属于落地文档的降级预案，不应未战先降。

## Consequences

- 数据字典需修订注明"posture 为运动代理实现"；真实方向姿态待固件 v2 补方向字段后升 feature_spec_version 并重训。
- 代理三态与字典四态的数值语义不同（0/1/2 含义不同），凡跨版本比较模型输出时必须留意。
